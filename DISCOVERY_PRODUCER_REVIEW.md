## Browser producer

Published route/product pages receive only a server-computed enabled boolean. No secrets or privileged client are passed to browser code. Enabled is false unless the existing collector configuration and trusted production runtime gates pass; local draft previews are excluded. With false, the client effect returns before allocating identity, touching sessionStorage, observing visibility or sending events. DNT/GPC also disables the producer; HTTP collector keeps its independent privacy checks.

One random UUIDv4 session is stored only in sessionStorage for the current browser tab, with memory fallback when storage is blocked. There is no cross-tab/long-lived user ID, fingerprint or persistent event queue. Each mounted page context gets its own pageViewId. Referrer, full URL/query, prose, Email and destination URL are not sent by this initial producer. Product view is emitted once when the document is visible. Strict effect cleanup/re-execution keeps identity/dedup refs for the same mounted context; actual page/path changes allocate a new context. BFCache restoration resumes the same mounted page view rather than counting a new distinct visit; this metric is not a unique-people measure.

Exposure definition is refined from the earlier whole card/row proposal: at least50% of a product-name entry link must be visible for one continuous second while the document is visible. Long table rows can exceed a mobile viewport, so a whole-row threshold would systematically undercount that layout. This is visibility of a product entry, not proof of reading all its conditions. Names in comparison rows and the later fit descriptions share one exposure ID/position for the same product/page; moving between them does not double-count. Leaving the viewport or hiding the document cancels timing. Observer/timers/listeners are disposed on effect cleanup. If IntersectionObserver is unsupported there is no fabricated impression fallback.

Normal and modified clicks, keyboard-generated link clicks and middle-button auxclicks on annotated product links dispatch product_click. The two official CTA/footer links dispatch outbound_click; evidence-source links are excluded. Hrefs and product/position metadata must match the server-provided page context. A quick click before the1-second visibility threshold remains an unmatched click diagnostic; it does not create an inferred impression or inflate CTR. Source-link/other navigation is unchanged.

Queue flushes every500ms, on tracked clicks, document hiding, pagehide and effect cleanup. Batches capped20 events/16KiB UTF8. pagehide uses same-origin application/json beacon if accepted by the browser, otherwise keepalive fetch; ordinary sends use keepalive fetch. No preventDefault or awaiting network before navigation. Failures are swallowed and there is no automatic retry/persistent queue. Delivery is best-effort: beacon acceptance is not server confirmation, network errors/rate refusal can lose events. The DB still deduplicates matching IDs. Production analytics health requires actual successful collector/storage verification, not simply queued requests.
